System Architecture & Edge Case Handling

Engineered for production resilience, adherence to Clean Architecture principles, and robust state consistency.

🔐

1. Authentication & RBAC

Industry-standard bcrypt password hashing with salt and PyJWT HMAC-SHA256 tokens. Strict user isolation ensures patients can only view and pay for their own bookings, while admin roles can manage catalog offerings.

🏥

2. Dynamic Centre-Test Pricing

Many-to-many relationship with CentreTest association table allows each diagnostic centre to configure custom test pricing, availability, and turnaround times. Price is permanently frozen on the Booking entity at creation.

📅

3. Booking State Machine

Finite state machine enforces strictly valid state transitions: PENDING ➔ CONFIRMED, PENDING ➔ FAILED, and CANCELLED. Validates appointments are in the future and within operating hours.

⚡

4. Webhook Idempotency & Locking

Dedicated webhook_events table indexes event_id. Uses database-level row locking (with_for_update) during execution to prevent race conditions during rapid concurrent duplicate webhooks.

🛡️

5. Price & Double-Pay Protection

Both payment simulation and webhook processors strictly enforce that incoming amounts match the frozen booking price, and immediately block double-payment attempts on already confirmed bookings.

🚀

6. Caching & Celery Background Tasks

Multi-tiered caching with automatic Redis connection and fallback to in-memory TTL caching. Celery workers handle background email/SMS dispatch and exponential-backoff retries.
